**Operating rules**

* The ledger records work that remains unresolved after the current turn's repair/execution evaluation: intentionally deferred work, work requiring a user decision or unavailable authority, genuine blockers, out-of-scope follow-up intentionally left for later, and other unfinished work that must survive the conversation. Do **not** create a ledger item merely because a problem was discovered when that problem is already authorized and executable now; perform the repair instead. If the repair succeeds and is verified in the same turn, no ledger item is needed.
* A `TBD`, `Unresolved`, or equivalent missing required value is unfinished work. The resolution type may differ: research, user decision, source verification, lived-use discovery, conflict reconciliation, or an explicit decision that the field is unnecessary.
* The ledger does not become authority for the underlying fact. Resolve the work in its true authoritative source, then close the ledger item.
* Domain-specific systems may expose or act on relevant ledger items, but must not maintain competing unfinished-work queues as separate sources of truth.
* New known unfinished work must not be left only in chat or memory.
* Prioritization happens here across domains so the user can compare work rather than having hidden domain backlogs.
