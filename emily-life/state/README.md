## State

Supabase personal-runtime is the sole operational record store for Emily Life. Store and reconcile inventory, quantities, locations, container contents, schedules, state, and operational events there. GitBook retains governing documentation only; never write or mirror operational records into GitBook. Current unknown values remain unknown; discarded historical data must not be used to reconstruct current state.

**What is true right now?**

State is Emily Life's maintained operational continuity authority. It records changing facts that must survive between executions without being reconstructed from briefings, recommendations, remembered conversation, historical prose, or copied summaries.

### Current-state rule

State is maintained from authoritative events and governed reconciliation. It is not a place to guess what probably happened.

Absence of a recorded fact means the fact is not currently established. It does not authorize reconstruction from a prior Morning Briefing, Dress Me output, search result, handoff, or historical example.

### Presentation Selection Ledger

Maintain the history of successfully validated presentation selections here.

Each entry records:

* date;
* atomic category identity;
* exact authoritative item or exact state selected;
* selection disposition;
* governing resolution context when needed.

A validated selection is presentation-selection history. It is **not** evidence that Emily actually wore or used the selection.

Presentation resolution may use this ledger to avoid repeatedly proposing the same items and to advance full-collection rotation.

### Lived Use Ledger

Maintain actual lived wear/use separately from presentation selections.

Add an entry only when the governing Emily Life experience establishes that Emily actually wore or used the item.

Each entry records:

* date;
* atomic category identity;
* exact authoritative item or state;
* lived-use status;
* any operational consequence required by the owning state system.

Lived-use history may drive laundry/wear state, depletion, current presentation continuity, and later rotation evidence.

Do not convert a recommendation or selected Morning Briefing look into lived use merely because it was proposed.

### Initialization boundary

Presentation-selection and lived-use tracking are initialized on **2026-10-04**.

Do not manufacture pre-initialization history.

Earlier history may be added only when a direct authoritative record explicitly establishes the actual selection or lived use. Search summaries, handoffs, prior assistant prose, and inferred outfit reconstruction are not sufficient evidence.

### Persistent presentation state

Maintain continuing presentation facts such as current manicure and pedicure treatment, already-established same-day presentation, and other presentation state that persists beyond one operation.

If the exact current state is not established, record it as unresolved rather than inventing a value from owned inventory or a historical visual example.
