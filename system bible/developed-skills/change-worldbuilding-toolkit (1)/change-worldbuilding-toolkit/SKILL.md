# Change Worldbuilding Toolkit

A story-agnostic reference system for Swap/Change fiction: keeping the rules of a change, who's currently who, how minds and bodies adapt, and how the world reacts all consistent scene to scene, session to session, with no shared memory between sessions except this skill and whatever story documents exist.

## What This Toolkit Governs (and What It Doesn't)

This toolkit governs **mechanisms** — events with a trigger, a scope, a duration, and a reversibility that need tracking so a later scene doesn't silently contradict an earlier one. A mechanism does not need to break the rules of reality to qualify: a mundane, deliberate disguise sustained by ordinary human effort is just as trackable as a magical body swap, provided a character has actually made an on-page choice that starts an ongoing state (see Gate 1, below). What it does NOT govern: realistic human behavior, misjudgment, or performance where no character ever makes a choice that starts a persistent, trackable state — nothing to log, because nothing is happening that a later scene could get wrong. Reference material (Reference A, B, C below) is free-standing factual content usable regardless of whether a mechanism is present at all — it answers "what does X actually consist of," not "why is this happening."

## Core Workflow

1. **New story:** read the master index first, pick only the modules that story needs.
2. **Before writing any transformation scene:** check Module 1's ledger and Precedent Log (Section 7) for this story. Check Section 3's "Explicitly Does Not Include" before extending any effect into schedule, occupation, relationships, or identity that was never named. Check Section 3C before inventing a baseline fact (wardrobe, possession) — generate a realistic placeholder scaled to the character's established status if one doesn't exist, mark it unverified, flag it.
3. **Before treating a mundane/behavioral scenario as trackable:** confirm Gate 1 — has a character actually made an on-page choice that starts an ongoing state? If it's still premise/discussion, there is nothing to log yet.
4. **Once Gate 1 is crossed (or any swap/change event occurs on the page):** ask the author directly for Trigger, Scope, Duration, and Reversibility — prefer a short set of concrete options — rather than guessing and flagging after the fact. Log the result in Section 7 in the same pass.
5. **When a skill, knowledge, or taste is marked as transferring (Section 3A):** write it as the donor's actual, specific, confident competence and judgment applied to the receiver's real situation — never a generic, hedged, or risk-averse approximation.
6. **When a scene needs a perceptual effect with guaranteed observer belief** (not just an unmanaged mundane disguise): use the Perceptual Swap addendum specifically, and apply the Illusion Confidence Rule — observers hold zero doubt, corrections are absorbed rather than refuted, and (per the Conformity Pressure Arc / Gendered Asymmetry in Consequence) pressure to conform escalates differently depending on which gender's presentation norms are being missed.
7. **When a scene needs sapphic community texture, trans presentation/transition detail, or ordinary daily-life logistics shaped by either:** don't build it here — use `sapphic-culture`, `gender-presentation-culture`, or `character-daily-texture` directly.
8. **Don't invent a new rule, cost, exception, or loophole silently** — if a scene needs something this ledger doesn't cover, flag it to the author and ask.
