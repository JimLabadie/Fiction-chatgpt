## Purpose

This is the durable home for every instruction to **put a pin in something**, return later, defer a decision, preserve an open question, or pause one subject for another.

A conversation, memory summary, routing note, source archive, or assistant promise is not a pin record. A pin exists only when this ledger records the subject, current understanding, reason for deferral, exact return point, affected components, and provenance.

This initial ledger is a backfill from the evidence currently verified. It is not yet a claim that every historical pin has been recovered. Missing historical pins remain an active persistence failure until the conversation archive and later ChatGPT state have been checked specifically for deferrals and return promises.

## Operating rule

When Jim says `put a pin in it`, `come back to this`, `later`, `not now`, or otherwise deliberately defers an active subject:

1. add or update the entry here before changing subjects;
2. preserve the current understanding rather than only the topic name;
3. identify the exact question or next action;
4. link any existing checkpoint or controlling component;
5. identify the source conversation or document;
6. commit and fetch the entry from GitHub; and
7. report the committed path and commit, not merely that the idea was “saved.”

No assistant may call a pin persisted merely because the relevant conversation is still visible or has been copied into the raw chat archive.
