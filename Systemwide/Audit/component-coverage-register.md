## Reading this register

This register answers two different questions without conflating them:

- **What exists in the preserved repository?** This can be established by paths, package members, and extracted content.
- **Has it been harmonized into a controlling reusable component?** This requires claim-level authority and version review.

`Destination exists` means a file exists. It does not mean the source family has been fully propagated. `Missing destination` means substantive material has no adequate controlling home yet; it does not mean the material is optional or rejected.

## Recovery queue rule

This register does not choose the next creative topic and does not silently prioritize one component as more important than another. It records the work honestly. When a component is selected for recovery:

1. assign every relevant source and package member;
2. compare exact duplicates, text matches, and meaningful variants;
3. recover Jim's decisions and distinguish them from assistant proposals;
4. persist the known accepted state even when fields remain open;
5. bring genuine conflicts to Jim;
6. create and link the controlling destination; and
7. fetch the published files back before reporting completion.
