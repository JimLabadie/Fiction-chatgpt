# Transform

Status: PROTOTYPE — NON-GOVERNING
Purpose: Resolve and propagate an explicitly selected character/world change without inventing unstated dimensions.

## Use when
A task involves a body, identity, role, trait, memory, perception, digital-record, presentation, age, ability, or other persistent change/swap whose consequences must remain coherent.

## Inputs
- active story/project namespace;
- current transformation mechanics and selected instance;
- affected entities and baselines;
- trigger, scope, duration, reversibility, and knowledge/consent state;
- applicable current governance and contextual knowledge.

## Procedure
1. Retrieve current governing transformation mechanics and the active instance/state.
2. Identify mechanism class and affected entities. Do not treat swap, change, perception, records, body, mind, role, or presentation as interchangeable.
3. Resolve the change envelope: trigger, explicit scope, exclusions, duration, reversibility, costs/side effects, knowledge, and consent/agency implications.
4. For every affected dimension, separate manifestation, functional capability, habits, declarative knowledge, episodic history, objects, perception, documentary/digital state, and social response where applicable.
5. Leave unspecified dimensions unchanged unless current governing mechanics explicitly establish another default. If a consequential event field is unresolved, stop for author resolution rather than inventing it.
6. Propagate only consequences entailed by the resolved envelope.
7. Call/use competence handling when changed circumstances require skills the character does not possess; context handling when culture/social interpretation materially affects consequences; presentation handling when appearance must be resolved; and state tracking for every persistent state transition.
8. Check elapsed story time before granting adaptation or competence.
9. Check observer/institution knowledge before writing reactions.
10. Audit the result against explicit exclusions and the pre-change baseline.
11. Hand persistent state changes to tracking/persistence. A transformation scene does not silently rewrite reusable mechanics.

## Guardrails
- Identity/personhood continues unless explicitly changed.
- A changed body/presentation does not automatically grant knowledge, skill, memory, interests, habits, relationships, occupation, or consent.
- Historical examples and cold tests are examples unless promoted by current authority.
- Older placeholder-generation instructions yield to current source-grounding and anti-invention governance.
- Never create a new mechanism rule, loophole, cost, exception, or precedent merely to make a scene work.
